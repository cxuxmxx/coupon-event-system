# 쿠폰 발급 워커 장애 복구

기술 오류로 발급을 완료할 수 없으면 같은 요청을 큐의 맨 앞에 두고 최대 다섯 번 시도합니다. 대기 간격은 1, 2, 4, 8, 16초입니다. 횟수를 소진하면 MySQL에 발급 이력이 있는지 확인합니다. DB 조회가 실패하는 동안에는 16초 간격으로 확인을 계속합니다.

발급 이력이 있으면 `ISSUED`로 완료합니다. 이력이 없음을 확인하면 요청을 DLQ에 남기고 결과를 `FAILED`로 기록합니다. 재고 소진과 같은 업무상 거절은 곧바로 `REJECTED`로 완료합니다.

## 조사 및 재접수

1. 요청 ID로 워커 로그를 찾고 Redis 해시 `coupon:{issue}:dead-letters`에서 원래 요청을 확인합니다.
2. MySQL의 `coupon_issue`에서 해당 쿠폰과 회원의 발급 이력을 조회합니다.
3. 발급되지 않았고 이벤트가 진행 중이면 정상 발급 API로 새 요청을 접수합니다. 재접수 건에는 새로운 대기 순서가 적용됩니다.
4. 조사에 필요한 기록을 남긴 뒤 확인을 마친 DLQ 항목을 제거합니다.

## 쿠폰별 병렬 발급

워커는 쿠폰마다 별도의 발급 큐와 락을 사용합니다. 같은 쿠폰에서 재시도 중인 요청은 큐 맨 앞에 남기고, 다른 쿠폰의 큐는 계속 처리합니다. 워커당 동시 처리 수는 `coupon.issue.worker.parallelism`으로 조정하며 기본값은 4입니다.

배포할 때 기존 워커를 종료한 뒤 새 워커를 띄웁니다. 새 워커가 기존 전역 발급 큐를 먼저 읽어 쿠폰별 큐로 옮깁니다. 전환 중에 두 버전의 워커를 동시에 실행하면 이전 워커가 새 발급 큐를 읽지 못합니다.

처리량을 비교할 때는 쿠폰 하나에 요청이 몰리는 경우와 여러 쿠폰에 분산되는 경우를 나누어 실행합니다. HTTP 202 응답 시간, 접수부터 완료까지 걸린 시간, 신청한 회원별 발급 건수와 잔여 재고를 함께 확인합니다.
